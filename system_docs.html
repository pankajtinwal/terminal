🎯 What This System Does

This is a fully serverless, zero-cost professional trading terminal for Indian markets. It tracks two separate watchlists — a curated Alpha 132 investment watchlist and an MTF swing-trading watchlist of 216 margin-eligible stocks — and synthesizes institutional-grade analytics for each.

The system answers two core questions: "How do my sector bets look as equal-weighted index charts?" and "Which stocks are showing quantitative signals worth acting on right now?"

Everything is computed by a Python script, committed as static JSON to GitHub, auto-deployed via Cloudflare Pages, and rendered in a React + Vite browser app — no backend server, no database, no cost.

💡 Core Design Philosophy

JAMstack architecture — Python computes data offline, commits static JSON to GitHub, and the React frontend fetches it directly. No runtime server. The "backend" is a scheduled GitHub Action + Python script running twice daily.

🔑 Key Design Decisions

• Dual watchlist — Investment + MTF mode, switchable at runtime
• Delta cache — only fetches new trading days each run
• Equal-weighting — no stock dominates by market cap
• React + Vite — full TypeScript component tree, zero global state libraries

Dual Watchlist System
Alpha 132 investment mode vs MTF swing-trading mode
🏗️ Architecture Overview

The dashboard supports two completely independent watchlists that can be switched in real-time using the navbar toggle. Each watchlist has its own set of computed JSON files and its own data pipeline processing path. The React app uses a WatchlistId type ('investment' | 'mtf') as the top-level state that drives all data fetching and view availability.

📊 Alpha 132 — Investment Watchlist

Purpose: Long-term portfolio management and sector analysis

• 132 hand-picked Indian small- and mid-cap stocks
• Synthesizes 14 equal-weighted indices (1 master + 13 sector)
• All 3 views available: Index Chart Heatmap Quant
• Data source files: indices_summary.json, heatmap_data.json, quant_models.json

⚡ MTF Stocks — Swing Trading Watchlist

Purpose: Swing trade candidate selection using 3.5x+ margin stocks

• 216 stocks eligible for MTF (Margin Trade Funding) at ≥3.5x margin
• No index chart view (not tracked as index constituents)
• Available views: Heatmap Quant
• Data source files: mtf_heatmap_data.json, mtf_quant_models.json
• Clicking a heatmap tile navigates directly to Quant Models with that stock selected

🔄 Runtime Switching Behavior

When the user clicks the Alpha 132 / MTF Stocks toggle in the navbar:

1. App.tsx calls handleWatchlistChange() which updates the watchlist state
2. If switching to MTF and current view is 'chart', the view auto-redirects to 'heatmap'
3. Both useIndexData and useQuantData hooks re-fire their refresh() callbacks, fetching the watchlist-specific JSON files
4. The selected quant ticker is reset to null to clear cross-watchlist state
5. The navbar center tab group dynamically shows/hides the "Index Chart" button based on watchlist

MTF Stock Selection Philosophy: The MTF watchlist is used to identify which stock to buy for a swing trade. The Quant Models + Heatmap combination lets you quickly spot momentum outliers and mean-reversion setups across 216 stocks simultaneously — a workflow that would take hours manually.

Data Ingestion Layer
How we pull and cache 348 stocks from Yahoo Finance
🔄 Delta Caching Strategy

Rather than re-downloading full history every run, the pipeline uses a delta cache approach:

1. On first run → download 1 year of daily OHLCV data for every stock and save to data/history.json
2. On subsequent runs → check the last date in cache per ticker, fetch only new trading days
3. Merge new rows into existing cache and re-save
4. The history.json file is excluded from the public/data/ sync (it can be very large and is not consumed by the frontend)

This reduces typical update time from ~15 minutes down to under 2 minutes.

⚠️ Anti-Ban Rate Limiting

Yahoo Finance throttles aggressive scrapers. The ingestion loop adds a random 1.5–3.0 second delay between each ticker fetch to avoid 429 errors.

time.sleep(random.uniform(1.5, 3.0))
🔧 Ticker Symbol Overrides

Some stocks have mismatches between NSE symbol and Yahoo Finance ticker. A SYMBOL_OVERRIDES dict handles these edge cases:

"TRIL" → "TARIL.NS" "INDEGENE" → "INDGN.NS" "PRICOL" → "PRICOLLTD.NS" "EMS" → "EMSLIMITED.NS" "KPGEL" → "KPGEL.BO" "LTIM" → "540005.BO" # MTF override
📁 Stock Metadata Formats

Stocks List.json (Investment) and MTF Stocks.json (Swing) both share this schema:

{ "ticker": "ZOMATO", "name": "Zomato Ltd", "sector": "Consumer Goods & Retail", "exchange": "NSE" }

The exchange field determines the suffix: NSE → .NS BSE → .BO

The --watchlist CLI flag controls which file is processed: --watchlist all (default in CI), --watchlist investment, or --watchlist mtf.

Index Math Engine
Equal-weighted index synthesis with Base 1000 normalization (Investment watchlist only)
📌 The Core Formula

Every stock's price history is normalized to a base of 1000 on the first day it appears. This removes price bias — a ₹5 stock and a ₹5000 stock contribute equally.

Normalized Price(t) = (Raw Close(t) / Raw Close(Day 0)) × 1000

The Index Value on any day is the arithmetic mean of all normalized prices in that sector:

Index(t) = Σ [Normalized_i(t)] / N   (where N = number of stocks)

Since all stocks start at 1000 on Day 0, the index also starts at 1000 — exactly like how Nifty started at 1000 on November 3, 1995.

🕯️ Synthesized OHLC Candlesticks

Each day's candle is synthesized:
• Open = mean of all stocks' normalized open
• High = mean of all stocks' normalized high
• Low = mean of all stocks' normalized low
• Close = mean of all stocks' normalized close

This gives a realistic candle with wicks and bodies, just like a real index candle.

📆 Multi-Timeframe Returns

6 return windows computed per stock & index:
1D 1 trading day back
1W 5 trading days back
1M 21 trading days back
3M 63 trading days back
6M 126 trading days back
1Y full year (first record)

🏭 Sector Qualification Rule

A sector only gets its own sub-index if it has 4 or more stocks. Smaller sectors are included in the Master Index but don't get a standalone chart.

Result: 1 Master Index + 13 Sector Sub-Indices = 14 total indices across all 132 investment stocks.

Heatmap Engine
Finviz-style squarified treemap built with D3-hierarchy — works for both watchlists
🗺️ Treemap Layout Algorithm

The heatmap uses D3's treemap() with the squarify tiling algorithm — the same technique used by Finviz and Bloomberg. It recursively subdivides a rectangle into child rectangles with aspect ratios as close to 1:1 as possible.

Tile size = absolute value of % return (or equal in Equal-Sizing mode). Bigger movers = bigger tiles.
Tile color = diverging red–green scale:

Quantitative Scatter Models
5 institutional-grade cross-sectional models for stock selection
📌 Architecture Overview

The Quant view renders 5 interactive scatter plots computed by build_indices.py using numpy + pandas. Each model takes the full price history of every stock and outputs per-stock (x, y) coordinates plus statistical metadata. The frontend (QuantScatterCanvas.tsx) renders these with a custom Canvas API renderer — no charting library — with OLS regression overlay, interactive tooltip, and click-to-lock selection.

The same 5 models are computed independently for both watchlists, outputting quant_models.json and mtf_quant_models.json.

Model 1 — EMA
EMA Mean Reversion Risk
X: % Distance from 50 EMA  |  Y: % Distance from 20 EMA
Identifies overbought rubber bands and pullback buy zones by plotting short-term vs medium-term EMA extension. Color encodes 200 EMA structural trend (Green = Bull, Red = Bear). Quadrant crosshair at (0,0) divides into 4 regimes. Stocks in Q3 (negative both axes, green) are the highest-quality pullback buys.
Model 2 — Momentum
Cross-Sectional Residual Momentum
X: 60-Day Log Return  |  Y: 5-Day Log Return
Identifies true idiosyncratic breakouts by regressing 5-day returns against 60-day returns. The OLS line shows the "expected" recent return given the longer trend. Stocks with studentized residuals above +2.0 (shown as outliers) are exhibiting genuine alpha — their recent move is not explained by the broad trend.
Model 3 — Kinematic
Velocity × Acceleration State Space
X: Standardized Price Velocity  |  Y: Standardized Price Acceleration
Treats price as a physical system. Velocity = 10-day momentum normalized by 60-day std dev. Acceleration = second derivative (momentum of momentum). Q2 stocks (positive velocity, negative acceleration) are at inflection — they were going up but are decelerating, signaling an imminent trend change. Mahalanobis distance identifies statistical extremes.
Model 4 — O-U Process
Ornstein-Uhlenbeck Mean Reversion
X: AR(1) Mean Reversion Speed (β)  |  Y: Current Spread Z-Score
Fits an AR(1) process to each stock's log price spread from its 20-day SMA. The fitted β coefficient indicates mean-reversion speed; z-score indicates current displacement. Stocks with high β (elastic) and extreme z-scores are the most tradeable mean-reversion candidates. Half-life = -ln(2)/ln(β) days.
Model 5 — Fractal
Hurst Exponent Regime Classification
X: Hurst Exponent (H)  |  Y: Distance from 50-Day SMA
Computes the Hurst exponent via R/S (Rescaled Range) analysis on 60-day return windows. H < 0.4 = mean-reverting (anti-persistent), H ≈ 0.5 = random walk, H > 0.6 = trending (persistent). Regime color-coding lets you quickly identify which stocks are in breakout-friendly trending regimes vs. chop. "Anti-Fade" stocks (H < 0.4, far from SMA) have the highest statistical probability of snapback.

🔁 GitHub Actions Workflow — 6 Steps
1
Checkout Repository
Uses actions/checkout@v4 to clone the full repo onto the runner.
2
Set Up Python 3.11 with pip cache
Uses actions/setup-python@v5 with cache: 'pip' to accelerate dependency installs on repeat runs.
3
Install Dependencies
Installs yfinance, pandas, numpy, and requests. numpy is required for quant model computation (Hurst exponent, OLS regression, Mahalanobis distance).
4
Execute build_indices.py --watchlist all
Processes both watchlists: loads cache → fetches new OHLCV → computes 14 indices + 5 quant models × 2 watchlists → writes all JSON files to data/.
5
Sync data/ → public/data/ (excluding history.json)
Copies all generated JSONs (except the large history cache) to public/data/ so Vite's build can serve them. history.json is excluded to keep the bundle small.
6
Commit & Push Changes
Stages data/ and public/data/ folders. Uses git diff --staged --quiet to skip commit if nothing changed (market holiday). Commit message includes [skip ci] to prevent infinite CI loops.
Zero Cost Automation: GitHub Actions gives 2,000 free minutes/month. Each run takes ~3–4 minutes (both watchlists). 2 runs/day × 22 market days = ~176 minutes/month — under 9% of the free quota.

Frontend Architecture
React 18 + Vite + TypeScript — component tree and data flow
🏗️ Technology Migration

The frontend has been fully migrated from a vanilla HTML/JS single-file to a Vite + React 18 + TypeScript application. This enables:

• Type-safe data contracts — all JSON shapes modelled in src/types/index.ts
• React hooks for data fetching (useIndexData, useQuantData)
• Hot Module Replacement during development
• Production build via npm run build → Cloudflare Pages auto-deploys from the dist/ output
• Tailwind CSS utility classes for styling

🔗 Data Hooks

useIndexData(watchlist) — fetches either:
• Investment: indices_summary.json + heatmap_data.json in parallel
• MTF: mtf_heatmap_data.json only (no summary needed)

useQuantData(watchlist) — fetches either:
• Investment: quant_models.json
• MTF: mtf_quant_models.json

Both hooks auto-refresh when the watchlist prop changes via useEffect dependency on the refresh callback.

How to Run Locally
Get the full pipeline + dashboard running on your machine
Step 1 — Install Python Dependencies
# Create a virtual environment (recommended) python3 -m venv .venv source .venv/bin/activate # Windows: .venv\Scripts\activate # Install required packages pip install yfinance pandas numpy requests
Step 2 — Run the Data Pipeline
# Process both watchlists (recommended, matches CI behavior) python build_indices.py --watchlist all # Or process only one watchlist: python build_indices.py --watchlist investment python build_indices.py --watchlist mtf # First run fetches ~1 year of history for all stocks # Takes 15-30 mins due to rate limiting (1.5-3s per stock) # Subsequent runs are fast — delta only (new days) ~2-4 minutes
Step 3 — Sync data/ to public/data/
# The React dev server serves files from public/ # Copy generated JSONs (exclude the large history cache) rsync -av --exclude="history.json" data/ public/data/ # On Windows (PowerShell): # robocopy data public\data /XF history.json /E
Step 4 — Start the React Dev Server
# Install Node.js dependencies (first time only) npm install # Start the Vite dev server with HMR npm run dev # Opens at: http://localhost:5173
Step 5 — Build for Production (Optional)
# Build the optimized production bundle npm run build # Preview the production build locally npm run preview # The dist/ folder is what Cloudflare Pages deploys automatically # on every git push to main.
Note on data/ vs public/data/: build_indices.py writes to data/ (your local cache). The React app reads from public/data/ in development and /data/ at runtime in production (served from Cloudflare Pages). Always sync after running the pipeline locally.
